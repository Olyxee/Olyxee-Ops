The project detail page should read as a practical workspace for actual tasks, people, files, and project identity. Avoid repeated narrative "snapshot" copy, multiple layers of metrics, and a pile of boxed dashboard cards that make it feel AI-generated.

**Why:** The user explicitly rejected the previous project detail design as looking AI-generated. Their broader visual preference is for restrained, readable interfaces, but this correction specifically targets the project page's generic presentation.

**How to apply:** When adding to the project detail page, use real project data and clear hierarchy. Keep status and attention work easy to scan without repeating the same facts in several decorative sections.
